# 종별 9종 확정 · 확인 화면 2항목 · 전월 결과파일 이력 누적 설계

작성일: 2026-09-01

## 배경 / 문제

세 가지가 한 번에 걸린다.

1. **종별 인식이 넓어지다 못해 뜻을 잃었다.** v5.4에서 청·지청별 표기 차이를 흡수하려고
   키워드 우선순위 규칙(`_SICK`/`_ANNUAL`/`_OFFICIAL_INJURY` …)과 40줄짜리 예시표
   (`CATEGORY_MAP`)를 넣었다. 그 결과 `조퇴`·`외출`·`지각`이 `기타`와 **같은 분류**가 되어,
   v5.4의 연가 상계가 네 종별에 똑같이 적용된다. 실제 기간제 조사관 근무상황에 찍히는
   종별은 9개뿐이므로, 넓은 규칙은 얻는 것 없이 규칙만 흐린다.

2. **종일 `기타` 행이 아무 효과가 없다.** `build_event()`는 사용시간이 없으면
   `minutes=0`으로 두고, `_worked_minutes_by_day()`는 결근·병가만 실근무 0분으로 본다.
   그래서 하루를 통으로 비우고 `기타`로 시간 없이 등록하면 **일급도 안 깎이고 식대도 나가고
   주휴·연가까지 발생한다.** 결근으로 정직하게 적은 사람만 손해를 본다.

3. **계약 시작월부터 다시 조회해 첨부해야 한다.** 연가·주휴는 계약 시작일부터 누적
   판정하므로(`coverage`), 7~9월 계약자의 8월 급여를 계산하려면 7·8월 근무상황을 모두
   첨부해야 한다. 그런데 7월 급여 계산 결과물에는 이미 7월 근무상황이 시트로 들어 있다
   (`output/raw_sheet.py`). 매달 조회 범위를 늘려 첨부하는 대신 전월 결과물을 이어받으면 된다.

## 목표

- 종별을 9개로 확정하고, 그 외에는 예외 없이 사람이 판단한다.
- `기타`를 조퇴·외출·지각에서 떼어내고, 종일 `기타`의 구멍을 막는다.
- 전월 결과파일이 과거 근무상황과 그때의 사람 판정을 나른다. 당월 근무상황만 첨부해도
  전체 소급이 가능하다.

## 확정 규칙

### 1. 종별 = 분류, 완전일치 9종

정규화(NFKC + 앞뒤 공백 제거)만 하고 아래 9개 문자열과 **완전일치**할 때만 인식한다.
안 맞으면 예외를 던지지 않고 확인 화면으로 보낸다.

| 종별 | 일급 | 식대 | 연가 잔량 | 만근(주휴·연가 발생) |
|---|---|---|---|---|
| `연가` | 미공제 | 지급 | 480분 소진 | 유지 |
| `반일연가` | 미공제 | 지급 | 240분 소진 | 유지 |
| `공가` | 미공제 | 지급 | — | 유지 |
| `일반병가` | 미공제 | 지급 | — | 종일이면 깨짐 |
| `결근` | 공제(전일) | 미지급 | — | 깨짐 |
| `조퇴`·`외출`·`지각` | 시간분 공제, 상계된 만큼은 미공제 | 지급 | 상계분 소진 | 8시간 전부면 깨짐 |
| `기타` | 시간분 공제(**상계 없음**), 종일이면 전일 공제 | 종일이면 **미지급** | — | 8시간 전부면 깨짐 |
| 그 외 전부 | 확인 화면 입력 | 확인 화면 입력 | — | 확인 화면 입력 |

보유 연가로 상계하거나 소진하는 종별은 `연가`·`반일연가`·`조퇴`·`외출`·`지각` 다섯이다.
`기타`는 연가 보유 여부와 무관하게 급여에서 깎는다.

`일반병가(진단서미첨부)`·`조퇴(연가처리)` 같은 괄호 표기는 현장에서 나오지 않는다는
전제다. 나오더라도 진행이 막히지 않고 확인 화면에서 사람이 고른다.

**단, 반일연가는 예외다(2026-09-02 확인).** 현장 표기가 `반일연가(오전)`·`반일연가(오후)`이므로
이 두 표기를 `반일연가`로 모으는 **닫힌 별칭표**(`mapping.ALIASES`)를 둔다. 오전/오후는 반차를
어느 시간대에 쓰는지만 다를 뿐 처리(240분 소진)가 같다. 별칭표는 키워드 규칙이 아니라 명시된
목록이라, 여기 없는 표기는 여전히 확인 화면으로 간다. 또한 정규화가 **공백을 전부 제거**하므로
`반일연가 (오전)`처럼 띄어 써도 인식된다(괄호·쉼표는 지우지 않는다).

### 2. 확인 화면 — 건별 2항목

올라오는 건은 두 종류다.

| 대상 | 기본값 |
|---|---|
| 9종에 없는 종별 | 없음 — 반드시 직접 고른다 |
| 인식된 종별이지만 **사유·비고에 값이 있는 행** | 규칙값이 미리 선택된 상태 |

항목은 건별 2개다.

- **지급**: `유급`(일급·식대 지급) / `무급`(둘 다 미지급)
- **주휴·연가 발생**: `발생함`(출근한 날로 봄) / `발생 안 함`(그 주 주휴·그 달 연가가 깨짐)

두 축은 독립이다 — "무급인데 주휴는 살아있음", "유급인데 만근은 깨짐"(종일 병가와 같은
모양)이 모두 표현된다. 연가 잔량 소진은 이 두 항목과 무관하게 종별 규칙대로 유지한다.

판정 단위는 지금과 같이 **원본 B파일 행 1건**(`person_key` + `source_range` + 원본 종별)이다.
하나라도 미선택이면 계산을 진행하지 않는다.

### 3. 전월 결과파일이 이력을 나른다

출력물의 `근무상황(기간제)` 시트에 열 2개를 덧붙인다.

| 열 | 값 |
|---|---|
| `지급판정` | `유급` / `무급` / 빈칸 |
| `주휴연가판정` | `발생` / `미발생` / 빈칸 |

확인 화면을 거친 행만 채우고, 규칙만으로 정해진 행은 빈칸으로 둔다(다음 달에 규칙으로
다시 판정하면 같은 결과가 나오므로 저장할 이유가 없다).

로드 흐름:

```
A파일 ─┐
B파일 ─┼─→ giganje_rows(합본) ─→ 기존 파이프라인 그대로
전월 결과파일 ─┘
   ├─ 임금내역(월중) 시트   → 전월 계약기간·실지급액   (기존, 소급용)
   └─ 근무상황(기간제) 시트 → 과거 근무상황 + 판정      (신규)
```

- **합치는 지점은 `core/parser.py` 한 곳**이다. 계산 엔진·소급·산정근거 화면·출력 시트는
  합본 `giganje_rows`를 받으므로 손대지 않는다.
- 중복 제거 키는 `(성명, 생년월일, 종별, 사용기간(날짜), 사용시간(시분))`이고 **당월
  B파일이 이긴다**(e-사람 원본이 정본). 사유·비고는 키에서 뺀다 — 나중에 채워질 수 있고,
  값이 달라졌다고 다른 건으로 볼 이유가 없다.
- 이어받은 행의 판정은 저장된 값을 그대로 쓰고 다시 묻지 않는다. 판정 열이 없는 구버전
  파일에서 온 행 중 확인 대상은 다시 묻는다.
- `coverage` 검증이 합본 기준으로 바뀐다. 당월분만 첨부해도 전월 파일이 이전 달을 채우면
  통과한다. 둘 다 없으면 지금처럼 차단하되, 안내문에 "전월 결과파일을 첨부하거나 계약
  시작월부터 다시 조회"를 넣는다.
- 부수 효과로 **소급 재계산이 정확해진다.** 지금 `retroactive.current_month_adjustments`는
  전월분을 당월 B파일 이벤트만으로 재계산한다(전월 근무상황이 없으면 그 달을 만근으로
  재계산한다). 합본이면 전월 실제 근무상황으로 재계산된다.

## 불변(변경하지 않는 것)

- 주휴(5-1)·연가(5-3) 판정 기준 자체. 그날 실근무 0분이면 만근이 깨진다는 규칙
  (`_worked_minutes_by_day`)은 그대로다 — 무엇이 실근무 0분인지에 `기타`(종일)와 확인
  화면의 `발생 안 함`이 추가될 뿐이다.
- 조퇴·외출·지각의 연가 상계(v5.4). 시간순 시뮬레이터(`simulate_leave_consumption`)도 그대로다.
- 급여 항목 계산식, 반올림 단위, 출력 시트의 열 구성(`임금내역(월중)`·`산정근거`).
- 전월 파일에서 계약기간·실지급액을 읽는 기존 경로(`load_previous_payroll`).

## 상세 설계

### `core/mapping.py` — 크게 줄어든다

키워드 규칙(`classify_by_rules`, `_ABSENCE`/`_SICK`/`_ANNUAL`/`_PUBLIC`/`_TRAVEL`/`_OTHER`/
`_OFFICIAL_INJURY`/`_HALF_*`)과 예시표(`CATEGORY_MAP`, `_NORMALIZED_MAP`)를 걷어내고 아래로
대체한다.

```python
KNOWN = ("연가", "반일연가", "공가", "일반병가", "결근", "조퇴", "외출", "지각", "기타")

def classify(raw_category) -> str:
    s = normalize(raw_category)          # NFKC + strip (구분자 제거는 하지 않는다)
    return s if s in KNOWN else UNDETERMINED_SPECIAL
```

- `normalize()`의 의미가 바뀐다. 지금은 괄호·쉼표·공백을 모두 지워 `조퇴(연가처리)`를
  `조퇴연가처리`로 만들지만, 이제는 **전각→반각(NFKC)과 앞뒤 공백만** 처리한다. 구분자를
  지우면 `조퇴(연가처리)`가 9종 어디에도 안 맞는다는 사실이 흐려진다.
- `full_day_weight()`는 `반일연가`만 0.5를 돌려주는 지금 동작을 유지한다.
- `full_day_breaks()`는 삭제한다(이미 미사용).
- `is_pending()`·`UNDETERMINED_SPECIAL`은 유지한다. 사람이 고른 결과는 분류 문자열이
  아니라 **이벤트의 두 필드**로 들어간다(아래).

### `core/models.py` — `LeaveEvent`에 판정 두 축을 싣는다

`classified` 문자열 하나로 급여·만근을 동시에 표현하던 것을 두 축으로 나눈다.

| 필드 | 뜻 | 규칙 종별에서의 값 |
|---|---|---|
| `classified` | 종별 9종 중 하나 또는 `특별휴가_미정` | 종별 그대로 |
| `unpaid` | 일급·식대 미지급(결근과 동일) | `결근`·종일 `기타` True, 나머지 False |
| `breaks` | 그날을 실근무 0분으로 본다(만근을 깬다) | `결근`·종일 `일반병가`·종일 `기타` True |

`breaks`는 **이미 있는 필드다**(과거 5-3 판정용으로 만들었다가 미사용으로 남아 있다).
주석을 고쳐 되살린다.

**확인 화면의 답은 `unpaid`/`breaks`만 채우고 `classified`는 절대 덮어쓰지 않는다.**
지금 코드는 확인 결과를 `classified = "유급특별휴가"`로 덮어쓰는데(`confirm_special_leave`),
사유·비고 때문에 확인 화면에 올라온 `연가` 행에 그렇게 하면 **그 연가의 잔량 소진이
사라진다**(`leave_usage_minutes`는 `classified == "연가"`로 판정한다). 분류는 원래 종별을
유지하고, 미인식 종별만 `특별휴가_미정` → `유급특별휴가`/`무급특별휴가`로 바꿔 화면·비고
표기에 쓴다.

`build_event()`에서 종일 `기타`를 결근과 같은 모양으로 만든다 — 이것이 문제 2의 수정이다.

### `core/payroll.py`

- `absence_days` 합산 조건: `결근`/`무급특별휴가` 문자열 비교 대신 **`e.unpaid and not e.is_time_based`**.
  식대(`meal_eligible_days = 기간일수 - absence_days`)는 이 값을 그대로 쓰므로 자동으로 맞는다.
- `public_leave_days`: `공가`/`유급특별휴가` — 유지.
- 상계 대상(`gita_covered`)을 `기타` → **`조퇴`·`외출`·`지각`**으로 바꾼다.
- 시간 공제 대상(`late_out_minutes`): 공제 제외 목록(`NON_DEDUCTIBLE`)을 `연가`·`반일연가`·
  `일반병가`·`유급특별휴가`로 바꾸고, `기타`는 상계 없이 전액 공제한다.
- 연가 부족 경고(`leave_shortfall`)의 모수도 `조퇴`·`외출`·`지각` 기준으로 바꾼다
  (`기타`는 애초에 상계하지 않으므로 부족 경고 대상이 아니다).

### `core/leave_engine.py`

- `_worked_minutes_by_day()`: 종일 비움 판정을 `e.classified in ("결근","병가")`에서
  **`e.breaks and not e.is_time_based`**로 바꾼다. 시간 기재분 합산(사유 무관)은 그대로다.
- `_consumes_leave_candidate()` / `simulate_leave_consumption()`의 상계 후보를
  `기타` → `조퇴`·`외출`·`지각`으로 바꾼다.
- `leave_usage_minutes()`도 같은 기준으로 바꾼다.

### `core/parser.py` — 합치는 지점

- `load_previous_status_rows(path) -> list` 신설. 전월 결과파일의 `근무상황(기간제)` 시트를
  읽어 B파일과 **같은 모양의 dict 행**으로 돌려준다(판정 2열 포함). 시트가 없으면 빈 리스트.
- `merge_status_rows(current_rows, previous_rows) -> list` 신설. 위 키로 중복을 제거하고
  당월을 우선한다. 순서는 이전 달 → 당월로 안정 정렬해 산정근거 화면과 출력 시트가
  날짜 순으로 읽히게 한다.
- `events_from_row()`는 판정 2열을 읽어 `unpaid`/`breaks`를 채운다(값이 있을 때만).

### `webapp/state.py`

- `load_files(a, b, prev)`: 전월 파일에서 근무상황을 읽어 합본을 만든 뒤 `build_target_people`에
  넘긴다. `previous_payroll`은 기존대로 같은 파일에서 읽는다.
- `collect_pending_groups()`: 확인 대상에 **사유·비고가 채워진 인식 종별 행**을 추가하고,
  그룹마다 규칙 기본값(`default_paid`, `default_accrual`)을 실어 보낸다. 전월 파일에서
  판정을 이어받은 행은 대상에서 뺀다.
- `confirm_special_leave(statuses)` → 두 축을 받는 형태로 바꾼다. 검증(개수 일치·미선택 차단)은
  유지한다.
- `prepare_calculation()`의 `coverage.find_coverage_gaps` 호출은 합본을 넘기므로 코드 변경 없음.

### `output/raw_sheet.py`

`COLUMNS`에 `지급판정`·`주휴연가판정`을 덧붙이고, 계산에 쓰인 합본 행을 그대로 쓴다.
`webapp/state.py:download()`가 이미 `giganje_rows`(합본)를 넘기므로 호출부는 그대로다.

### `gui/` (tkinter)

`gui/special_leave_screen.py`도 같은 2항목으로 맞춘다. 현재 배포 경로는 pywebview 웹 UI지만
`gui/`가 아직 남아 있으므로 규칙이 갈라지지 않게 함께 고친다.

## 테스트 계획 (TDD)

새로 고정할 것:

1. `mapping.classify`가 9종은 그대로, 그 외(`일반병가(진단서미첨부)`, `공무상병가`,
   `관외여행`, `경조사휴가`, 빈 문자열)는 전부 `특별휴가_미정`.
2. 종일 `기타` 1일 → 일급 공제 + 식대 미지급 + 그 주 주휴 미발생 + 그 달 연가 미발생.
3. 부분시간 `기타` 3시간 → 시간분만 공제, 식대 지급, 만근 유지, **연가 잔량 불변**(상계 없음).
4. 부분시간 `조퇴` 3시간(보유 연가 있음) → 급여 미공제, 연가 잔량 180분 감소(v5.4 회귀 방지).
5. 확인 화면 `무급`+`발생 안 함` 종일 건 → 결근과 동일한 결과.
   `유급`+`발생 안 함` → 급여는 지급되나 주휴 미발생(종일 병가와 동일).
6. 사유가 채워진 `연가` 행이 확인 대상으로 올라오고, 기본값이 `유급`/`발생함`이다.
   그 상태로 확인해도 **연가 잔량이 480분 소진된다**(분류를 덮어쓰지 않는다는 것의 고정).
7. `merge_status_rows`: 같은 키 중복 제거, 당월 우선, 순서 안정.
8. 전월 결과파일만으로 7월이 채워져 8월 계산이 `coverage` 차단 없이 통과한다.
9. 전월 파일에 저장된 판정이 있는 행은 확인 화면에 다시 올라오지 않는다.
10. 라운드트립: 계산 → 저장 → 그 파일을 전월 파일로 다시 로드 → 같은 근무상황·판정이 복원된다.

기존 테스트 중 종별 문자열(`병가`·`기타`)에 의존하는 것들은 새 규칙에 맞춰 갱신한다.
`조퇴`가 `기타`로 분류되던 것에 기대는 단정은 전부 바뀐다.
