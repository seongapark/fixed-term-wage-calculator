# 특별휴가(유급/무급) 처리 + 공가·결근 급여 반영 버그 수정 + 주휴수당 판정 로직 최신화 설계

> 관련 코드: `wage_calculator/core/{mapping,models,parser,leave_engine,payroll}.py`, `wage_calculator/gui/*`, `wage_calculator/output/wage_sheet.py`

## 1. 배경

e-사람(내부망) 근무상황 파일을 지역별로 다운로드하면, 종별 컬럼에 `가족돌봄휴가`, `여성보건휴가`, `경조사휴가` 같은 세부 특별휴가 명칭이 아니라 **"특별휴가"라는 뭉뚱그린 값만** 찍혀 나오는 경우가 있다. 특별휴가는 유급/무급에 따라 급여 처리(일급·정액급식비 지급 여부)가 달라지는데, 원본 파일만으로는 이 둘을 구분할 수 없다. 사유/비고 컬럼은 지역마다 기재 여부가 달라 신뢰할 수 없는 값이라 자동 판정 근거로 쓸 수 없다.

이 작업을 설계하며 기존 `payroll.py`의 공가/결근 급여일수 계산식에 방향이 반대로 뒤집힌 버그가 있는 것을 발견해, 특별휴가 로직을 얹기 전에 먼저 고친다(사용자 확인 완료).

또한 `leave_engine.py`의 5-1(주휴) 판정 조건 중 두 가지가 근로기준법 최신 기준과 어긋나 있는 것을 발견해 함께 수정한다(§8, 사용자 확인 완료).

## 2. 확정된 요구사항

- **공가 / 연가**: 유급, 정액급식비 지급, 주휴·연차 발생에 영향 없음(기존 동작 유지 대상)
- **유급 특별휴가**: 일급·정액급식비 지급, 주휴·연차 발생에 영향 없음 → **공가와 급여 처리상 완전히 동일**
- **무급 특별휴가**(가족돌봄휴가, 생리휴가 등): 일급·정액급식비 **미지급**, 주휴·연차 발생에는 **영향 없음**(결근과 다른 점) → 급여일수 계산에서는 결근과 동일하게 취급하되, 주휴/연차 판정에서는 결근과 달리 "안 깨짐"
- 특별휴가의 유급/무급은 **원본 데이터로 자동 판정 불가** → 화면에서 건별(그룹별) 수동 선택 필요
- 임금내역(월중) 출력 시트는 **열 구성이 고정**(7-0 명세, 임의 변경 금지)이라 특별휴가 전용 열을 새로 만들 수 없음 → 유급 특별휴가는 기존 "공가(일)" 열에, 무급 특별휴가는 기존 "(결근)" 열에 합산하고, 비고란과 헤더 셀 코멘트로 구분 표기

## 3. 기존 버그: 공가·결근이 급여일수(계일)에 반대로 반영됨

`payroll.py`의 기존 식:

```python
actual_workdays = workdays - public_leave_days - (paid_holiday_days + absence_days)
total_days = actual_workdays + paid_holiday_days + absence_days
```

대수적으로 정리하면 `total_days = workdays - public_leave_days`가 되어:
- 공가(유급이어야 함)를 쓸수록 `total_days`가 줄어 급여가 깎임
- 결근(무급이어야 함)은 더했다가 그대로 다시 빼져서 `total_days`에 전혀 영향을 주지 않음(결근해도 급여 그대로 지급)

**수정 후 식**:

```python
actual_workdays = workdays - public_leave_days - (paid_holiday_days + absence_days)  # 변경 없음(표시용 "실출근" 정의 유지)
total_days = actual_workdays + paid_holiday_days + public_leave_days                  # 결근 대신 공가를 다시 더함
```

대수적으로 `total_days = workdays - absence_days`가 되어, 공가는 급여에 영향 없고 결근만 그날치가 빠지는 정상 동작이 된다.

## 4. 데이터 흐름 / 매핑 계층

### `mapping.py`
- `CATEGORY_MAP`에 `"특별휴가": "특별휴가_미정"` 추가
- 목록에 없는 다른 종별은 지금처럼 즉시 `ValueError`(안전장치 유지) — "특별휴가"만 임시 분류를 통과시킴
- `full_day_breaks()`: `"특별휴가_미정"`은 `False`(유급/무급 확정 후에도 둘 다 안 깨지므로 임시 상태도 동일)
- `full_day_weight()`: 특별휴가는 반일 카테고리가 아니므로 기본값 1.0

### `parser.py`
- "특별휴가" 종별 행은 지금처럼 요일별로 펼쳐서 `LeaveEvent`를 즉시 생성하되 `classified="특별휴가_미정"` 상태로 둠(별도 펜딩 자료구조 없음)
- 시간 기재분(사용시간(시분) 있는 경우)은 기존 공통 규칙(모든 시간 기재 항목은 사유 무관 무조건 깨짐)을 그대로 따름 — 특별휴가 전용 예외 없음

## 5. 화면(마킹 UI)

- **삽입 위치**: `UploadScreen._next()` → `app.load_files()` 직후. 로드된 이벤트 중 `classified == "특별휴가_미정"`가 하나라도 있으면 신규 `SpecialLeaveScreen`을 표시, 없으면 지금처럼 바로 대상자 확인 화면으로 진행(기존 사용자 경험 변화 없음)
- **표시 내용**: `성명 | 날짜(범위) | 사유(원본, 있으면) | 비고(원본, 있으면) | 유급/무급 선택`
- **그룹화**: 원본 B파일 한 행(같은 사람의 연속 날짜 범위)에서 펼쳐진 이벤트는 한 그룹으로 묶어 한 번만 선택 → 그룹 내 모든 날짜에 동일 적용
- **진행 제약**: 모든 그룹에 유급/무급이 선택되기 전까지 "다음" 비활성화(기존 `missing_names`/`ambiguous_names` 진행 차단 패턴과 동일 원칙)
- **확정 반영**: 선택 완료 시 그룹 내 각 `LeaveEvent.classified`를 `"유급특별휴가"` 또는 `"무급특별휴가"`로 갱신

## 8. 주휴수당(5-1) 판정 로직 최신화

### 문제 1: 15시간 요건을 매주 실근무시간으로 재검증하고 있음

[leave_engine.py:97-98](../../../wage_calculator/core/leave_engine.py):
```python
elif total_worked_minutes < 15 * 60:
    granted, reason = False, "주 실근무시간 15시간 미만"
```

"4주 평균 소정근로시간 15시간 이상"은 초단시간 근로자 여부를 가르는 **계약상 기준**이지, 매주 실제 근무시간을 다시 재는 기준이 아니다(주휴수당 금액도 실근로시간이 아닌 소정근로시간 기준으로 고정됨). 주5일 8시간(주40시간) 계약자는 이 요건을 계약 자체로 이미 만족하므로, 이 조건은 **완전히 삭제**하고 재검증하지 않는다.

### 문제 2: "다음 근무 예정일" 요건이 2021년 이전 행정해석을 따르고 있음

[leave_engine.py:89, 99-100](../../../wage_calculator/core/leave_engine.py):
```python
has_next_day = eff_end < contract_end
...
elif not has_next_day:
    granted, reason = False, "근무 연속성 없음(계약 마지막 주)"
```

2021.4.7 행정해석 변경(임금근로시간과-1736) 이후 기준은 "그 주 주휴일까지 근로관계가 유지되면 발생, 그 다음 주 근무 예정 여부는 무관"이다. 이 7일 창 구조에서는 `nominal_end`(창의 명목상 종료일, 계약으로 안 잘렸다면 실제 종료일)가 그 주의 주휴일에 해당하므로, 판정 기준을 다음과 같이 교체한다.

```python
reaches_week_off_day = eff_end == nominal_end
...
elif not reaches_week_off_day:
    granted, reason = False, "근로관계가 그 주 주휴일까지 유지되지 않음(계약 종료로 주휴일 이전 근로관계 종료)"
```

`total_worked_minutes` 변수(문제 1 조건에서만 쓰이던 값)는 함께 제거한다. `by_day`/`worked_days`는 조건 ②(실근무 없는 날)에 계속 필요하므로 유지.

**실제 영향**: 계약이 보통 금요일(마지막 근무일)에 종료되는 이 조직의 실무 관행상, `eff_end`(금요일)는 `nominal_end`(일요일)에 못 미치므로 결과는 **지금과 동일하게 미발생** — 즉 일반적인 계약 마지막 주 판정은 바뀌지 않는다. 계약 종료일이 예외적으로 그 주 주휴일까지 연장되는 경우에만(현재 코드는 미발생, 수정 후 코드는 발생) 실제로 결과가 달라진다.

## 11. 산정로직 참고문서 (신규 산출물)

프로그램과 별개로, 급여 결과를 사람이 검토할 때 "왜 이 숫자가 나왔는지" 추적할 수 있는 **평문 텍스트 파일**을 프로젝트 루트에 함께 생성한다(파일명 예: `임금계산_로직_안내(v3.0).txt`).

**성격**: 버전 이력이나 변경사항 나열이 아니라, **v3.0 기준 현재 로직이 어떻게 동작하는지 스냅샷으로 정리**한 문서. 표는 쓰지 않고, 이해하기 쉬운 구체적 예시 위주로 서술.

**포함 내용**:
1. 종별(결근/공가/연가/반일연가/병가/기타/유급특별휴가/무급특별휴가/유급휴일)별로 유급 여부·정액급식비 지급 여부·주휴/연차 발생 영향을 평문으로 정리
2. 주휴수당 발생 규칙(§8 반영분 포함: 개근 판단 기준, 계약 마지막 주 판단 기준)을 실제 날짜 예시로 설명
3. 정액급식비가 근무상황에 따라 어떻게 일할 계산되는지(`daily_meal`, `meal_eligible_days`, 계산식)를 예시 숫자로 설명

작성 시점은 이번 구현이 모두 끝난 뒤(코드가 실제로 그렇게 동작하는 상태에서) 최종적으로 정리한다 — 구현 중간에 로직이 바뀌면 문서도 같이 갱신.

## 10. 테스트 범위

- `mapping.classify("특별휴가")` → `"특별휴가_미정"` 반환, 미등록 종별은 여전히 예외
- 유급/무급 확정 후 `leave_engine`의 주휴(5-1)·만근(5-3) 판정이 공가/기타와 동일하게 "안 깨짐"으로 처리되는지
- `payroll.py`: 공가만 있는 케이스에서 `total_days`가 줄지 않는지, 결근만 있는 케이스에서 정확히 결근일수만큼 줄어드는지(§3 버그 수정 검증)
- 유급특별휴가가 공가 버킷에, 무급특별휴가가 결근 버킷에 정확히 합산되는지
- `meal_eligible_days`에 무급특별휴가가 반영되는지
- `wage_sheet.py` 비고란 텍스트 포맷 및 헤더 코멘트 존재 여부
- 5-1: 지각/조퇴/외출이 몰려 그 주 실근무시간 합계가 15시간 미만이어도(전일 결근·병가 없이 개근한 경우) 주휴 발생 처리되는지(§8 문제 1 검증)
- 5-1: 계약이 그 주 주휴일(`nominal_end`)까지 연장된 마지막 주는 발생, 금요일 등 주휴일 이전에 종료되는 일반적인 마지막 주는 미발생 처리되는지(§8 문제 2 검증)
