# 조퇴/외출/지각의 연가 상계(offset) 설계

작성일: 2026-08-14

## 배경 / 문제

현재 조퇴/외출/지각(원본에서 종별 "기타"로 등록되며 사용시간이 기재된
`is_time_based` 이벤트)은 **무조건 분단위로 급여에서 공제**된다.

- `payroll.calc_payroll`: `late_out_events = [e for e in period_events if e.is_time_based]`
  → `late_out_minutes` → `late_out_deduction` → `base_pay = gross_pay - late_out_deduction`
- 연가(월차) 잔량은 명시적 "연가/반일연가" 이벤트만 소진(`leave_engine.leave_usage_minutes`).

그러나 7~9월 같은 기간제 계약자는 7월 만근으로 한 달 뒤(8월) 연가가 1일 발생하고,
그 뒤 조퇴/외출/지각을 쓸 수 있다. 이 경우 **보유 연가가 있으면 급여를 깎는 대신
연가에서 차감**하고, 급여는 그대로 두되 **마지막 달 연가보상비가 그만큼 줄어드는**
것이 올바른 처리다.

## 목표

조퇴/외출/지각 시간을, 그 **사건 날짜 시점에 가용한 연가 잔량 한도 내에서** 연가로
상계한다. 상계된 시간은 급여 공제 대상에서 제외되고 연가 사용으로 기록되어 잔여
연가(→마지막 달 연가보상비)를 감소시킨다. 연가로 다 덮지 못한 초과분만 종전처럼
분단위 급여 공제한다.

## 확정 규칙

1. **부족분만 급여 공제**: 사건 날짜 기준 가용 연가로 덮고, 넘치는 시간만 분단위
   급여 공제.
2. **사건 날짜(as-of) 기준 가용분만**: 연가 발생(만근 다음 달, 구간종료+1일부터
   가용) 전에 쓴 조퇴/외출/지각은 연가로 못 막고 급여 공제.
3. **부족 경고**: 조퇴/외출/지각 사용분이 보유 연가보다 많아 급여 공제가 남는
   사람은 경고 메시지를 표시한다.

## 불변(변경하지 않는 것)

- **주휴(5-1)/만근(5-3) 판정은 그대로.** `_worked_minutes_by_day`는 조퇴/외출/지각
  분을 실근무에서 계속 차감한다. 연가 상계는 "급여를 어디서 빼느냐"의 재배치일 뿐,
  근태상 자리를 비운 사실 자체는 변하지 않는다.
- 명시적 연가/반일연가 사용의 기존 동작(잔량 차감)은 그대로 유지.
- 종별 매핑(`mapping.py`)은 변경 없음. 조퇴/외출/지각은 여전히 "기타"로 분류된다.

## 입력 데이터 요건 (중요)

연가 잔량은 **계약기간 전체**의 만근 이력(발생)과 연가·조퇴/외출/지각 사용
이력(소진)에 의존한다. 따라서 업로드되는 근무상황(B파일)은 **해당 계약자의 계약
전체 기간을 커버**해야 정확하다.

- 앞달 행이 누락되면 그 달이 "무결근=만근"으로 오인되어 연가가 과다 발생하거나,
  앞달에 쓴 연가/조퇴가 안 보여 잔량이 과다 계산된다.
- **소급 경로도 동일**: `retroactive.current_month_adjustments`는 전월분 재계산에도
  당월 B파일 이벤트(`person.events`)를 재사용한다. 당월 B파일이 계약 전체 이력을
  담고 있으면 당월·소급 계산 모두 별도 배관 변경 없이 정확해진다.

이 요건은 코드 변경 사항이 아니라 **운영/입력 전제**다. 코드(`calc_payroll`)는 이미
`person.events`를 통째로 받아 연가 창을 계산한다. 문서와 (선택적으로) 화면 안내에
이 전제를 명시한다.

## 접근: 시간순 연가 소진 시뮬레이터

as-of 날짜 기준 가용, 부족분 분리, 연가·조퇴/외출/지각 혼용을 동시에 만족하려면
계약 전체 이벤트를 **날짜순으로 한 번 걸으며 잔량을 갱신**하는 방식이 필요하다.

### 새 함수: `leave_engine.simulate_leave_consumption(monthly_windows, events)`

계약 전체에 대해 다음을 계산한다.

- **발생 타임라인**: 각 만근 구간 `w`에 대해 `available_from = w.effective_end + 1일`
  시점에 `+480분`. (`w.accrued`가 True인 구간만)
- **소진 이벤트**(날짜순 정렬):
  - 명시적 연가/반일연가: `leave_usage_minutes(e)`분을 잔량에서 차감(종전 동작 유지,
    잔량 부족해도 그대로 차감 → 음수 허용, 기존 정책 유지).
  - 조퇴/외출/지각(`is_time_based` 그리고 `classified == "기타"`): 그 사건 날짜 시점의
    **양(+)의 가용 잔량 한도 내에서만** 연가로 덮는다.
    - `covered = min(event.minutes, max(balance_at_date, 0))`
    - `covered`만큼 잔량에서 차감(연가 사용으로 기록).
    - `uncovered = event.minutes - covered` → 급여 공제분으로 남긴다.

정렬은 날짜 오름차순. 같은 날짜에 발생(+480)과 소진이 겹치면 발생을 먼저 반영해
그날 발생분을 그날 사건 상계에 쓸 수 있게 한다. 같은 날짜에 명시적 연가와
조퇴/외출/지각이 함께 있으면 **명시적 연가를 먼저** 소진(의도된 사용 우선).

반환(제안):

```
LeaveConsumption:
  offset_minutes_by_event: dict[event_id -> int]   # 각 조퇴/외출/지각의 연가로 덮인 분
  total_offset_minutes: int                        # 조퇴/외출/지각 상계 합계
  total_uncovered_minutes: int                     # 급여 공제로 남은 합계
  shortfall: bool                                  # total_uncovered_minutes > 0 (경고용)
```

`event_id`는 안정적 식별을 위해 `id(event)` 대신 `(d, time_start, minutes,
raw_category)` 또는 이벤트 객체 참조를 사용(구현 시 결정).

### `payroll.calc_payroll` 변경

- 계약 전체에 대해 `simulate_leave_consumption` 실행.
- **급여 공제**: `late_out_minutes`를 "급여기간 내 조퇴/외출/지각 이벤트의
  **uncovered 분** 합계"로 계산(종전엔 전체 minutes 합계였음). `late_out_deduction`은
  이 uncovered 합계로만 산정.
- **연가보상비**: 조퇴/외출/지각의 covered 분이 잔량 소진에 반영되도록,
  `leave_balance_minutes_as_of`가 조퇴/외출/지각 상계분도 함께 차감하도록 확장하거나,
  시뮬레이터가 계산한 최종 잔량을 사용한다. `remaining_leave_days`는 이 반영된
  잔량으로 산출 → 마지막 달 `leave_compensation` 자동 감소.
- **경고**: `PayrollResult`에 `leave_offset_minutes:int`,
  `late_out_uncovered_minutes:int`, `leave_shortfall:bool`(및 사람이 읽을 경고
  문구 문자열) 필드 추가.

### `leave_balance_minutes_as_of` / 원장(`build_leave_ledger`) 정합성

증거자료용 이력 원장과 급여용 스냅샷 잔량이 서로 어긋나지 않도록, 조퇴/외출/지각
상계분을 **연가 사용의 일부**로 동일하게 취급한다. 구현 방식 2안 중 택1(플랜 단계
결정):

- (A) `leave_usage_minutes`를 확장해 조퇴/외출/지각의 covered 분을 사용분으로
  반환하게 하되, covered는 시뮬레이터가 사전 계산한 값을 참조.
- (B) 원장/스냅샷 계산 함수에 시뮬레이터 결과(offset)를 주입.

핵심 요건: **7-4 증거자료의 연가 원장과 임금내역의 급여 공제·연가보상비가 한
소진 이력에서 일관되게 도출**되어야 한다.

## 경고 노출 위치 (확정)

- **"계산" 실행 시 팝업(모달)으로 안내**한다. 부족(초과)이 발생한 인원 명단과 각자의
  초과시간을 한 번에 모아 보여준다
  (예: "○○○: 조퇴/외출/지각 Xh 중 Yh는 연가로 상계, 초과 Zh는 급여 공제됨").
  - 서버(`state.py` 계산 경로)가 사람별 shortfall 정보를 모아 계산 응답에 실어
    보내고, 프론트(`upload.js`/계산 트리거 쪽)가 계산 완료 시 모달로 표시한다.
  - 부족 인원이 하나도 없으면 팝업을 띄우지 않는다.
- **시트(임금내역/산정근거) 비고에는 미기재**(YAGNI).

## 테스트 계획 (TDD)

`leave_engine`/`payroll` 단위 테스트로 다음 시나리오를 커버:

1. **발생 전 지각**: 7월 계약 시작, 7/10 지각 4h. 아직 연가 0 → 전액 급여 공제,
   상계 0.
2. **정상 상계**: 7월 만근 → 8/1 연가 1일 발생. 8/10 조퇴 4h → 0.5일 연가 상계,
   급여 공제 0, 잔여연가 0.5일, 마지막 달 연가보상비 0.5일분.
3. **부족(초과)**: 보유 8h인데 조퇴/외출/지각 합계 10h → 8h 상계 + 2h 급여 공제 +
   `shortfall=True` 경고.
4. **명시적 연가와 혼용/우선순위**: 같은 가용 잔량을 명시적 연가가 먼저 소진 후
   남은 분으로 조퇴 상계.
5. **소급 정합**: 계약 전체 이벤트가 주어졌을 때 전월 재계산의 잔량/보상비가
   당월 계산과 일관.
6. **주휴/만근 불변**: 조퇴/외출/지각 상계가 주휴·만근 판정 결과를 바꾸지 않음.

기존 테스트(`test_payroll_*`, `test_leave_engine_*`, `test_end_to_end_v3`)가
회귀 없이 통과해야 한다. 조퇴/외출/지각이 없는 계산은 결과가 완전히 동일해야 한다.
